Abstract

This project asks whether the grammatical structure of a language can be used as a design parameter to reduce the computational cost of training language models. The central question is whether morphology-aware tokenization - which encodes grammatical structure explicitly rather than relying on statistical subword fragments - allows a model to learn a language more efficiently under identical architecture and data.

The project spans nine languages chosen to cover the full morphological spectrum: Mandarin (isolating), English (analytic), German and Spanish (fusional), Hungarian (agglutinative-fusional), Turkish (agglutinative), plus three structural outliers - Arabic (root-and-pattern templatic), Swahili (classificatory), and Basque (polypersonal, language isolate). Nine language-specific grammar engines have been built and tested (5,079 tests, zero failures). Each language is paired with a standard BPE baseline and a grammar-aware morphological variant under identical architecture.

A Phase 1 pilot across English, Arabic, and Turkish at 2M parameters / 5M tokens showed a monotonic gradient matching morphological complexity exactly: Turkish improved by 56.9%, Arabic by 13.9%, English by ~1%. Phase 3 extends the mini experiment to all nine engines. The project contributes nine reproducible grammar engines, a shared training pipeline, and an empirical framework for evaluating linguistic efficiency as a design variable in machine learning systems.

1. Research Question

1.1 The Core Idea

Language models learn by processing tokens - discrete units of text. Standard tokenizers (BPE, WordPiece) produce tokens by merging frequent character sequences, with no knowledge of grammar. The word researchers might become research + ers, depending on what the algorithm saw most often during training. The grammatical information - that this is a plural noun derived from a verb - is not encoded anywhere. The model has to infer it from context, across millions of examples, at cost.

Hypothesis

A language model given explicit morphological structure at the token level will learn more efficiently - reaching the same perplexity with fewer training tokens - than one using standard BPE subword tokenization. The effect will be strongest where morphology is richest.

1.2 Language as a Compute Efficiency Variable

Every training token costs compute. If a model needs N tokens to learn a grammatical pattern that could have been encoded directly in the tokenization, those N tokens represent overhead - compute spent recovering information that was always present in the text but stripped out by the tokenizer. That is not a small observation. At current GPU rental prices, even a few percent reduction in total tokens translates into a visible difference across many runs or large models.

This overhead is not uniform across languages. English grammar is largely carried by word order. Arabic and Turkish pack substantial grammatical content into word form: a single Turkish word can encode tense, aspect, mood, person, number, case, and possession simultaneously. A morphology-aware tokenizer can represent that word as a single structured token with the full grammatical bundle attached. The question is whether the model actually benefits from receiving that information upfront, or whether it would have figured it out anyway.

1.3 Morphology as Information Compression

From an information-theoretic perspective, morphological tokenization is a form of lossless compression applied to grammatical content. Instead of distributing grammatical information across multiple BPE fragments, it concentrates that information into a single token with an explicit feature label. The model receives more signal per token, which should translate to faster convergence at equivalent token budgets. Whether it actually does - and by how much, and for which languages - is what this project tries to measure.

3.1 The Nine Grammar Engines

Each language has a structurally different morphology, so each needed its own engine. The engine's job is to decompose each word into a root (or stem) and a grammatical bundle before it reaches the model. Nine engines totalling ~5,690 lines of Python are built and passing 5,079 tests (zero failures). For Arabic, the engine draws on the Buckwalter morphological analyser and the Doha Historical Dictionary of Arabic root lexicon for triconsonantal root lookup and wazn pattern assignment. For Turkish, it uses Oflazer's two-level morphology as a reference for suffix slot ordering. English uses a rule-based lookup against a custom irregulars table. Mandarin uses jieba for word segmentation. Turkish - the grammar hint made a huge difference 56.9% better

Turkish words are built by stacking suffixes - one root word can become dozens of different words depending on what you attach to it. Telling the model "this suffix means past tense" or "this one means plural" let it learn the language almost twice as well with the same amount of training data. That is a large number for a small change in how the input is structured.

Arabic - a meaningful improvement 13.9% better

Arabic builds words from roots combined with vowel patterns and affixes. The same root produces dozens of related words across different patterns. Telling the model the root and the pattern helped it recognise those relationships faster. The improvement would likely be larger with a bigger vocabulary - 19% of words were cut as unknown due to memory limits, which penalises the morph model unfairly.

English - almost no difference 1% difference

English has relatively simple word structure - most grammatical information is carried by word order, not word form. Standard tokenization already handles English well enough that the extra grammar hint adds almost nothing. This is the expected result, and it is actually important: it means the improvement in Turkish and Arabic is not a general artifact of the method, but something specific to morphological richness.

5. Discussion

What the Phase 1 results mean

The efficiency gradient - ~1% for English, 13.9% for Arabic, 56.9% for Turkish - is monotonic and matches the predicted ordering of morphological complexity. It is not just that the morph model did better in some cases - the ordering was exactly right. Morphology increases information density per token. When a model receives a structured token encoding root identity and grammatical role, it does not need to spend training steps inferring that structure from context. The more grammar a language encodes in word form, the more there is to compress, and the larger the efficiency gain from doing so explicitly. Phase 3 will test whether this gradient generalises across the full nine-language spectrum.

5.1 Limitations

Phase 1 scope - three languages only

The monotonic gradient is drawn from three data points. It is directional, not conclusive. Phase 3 extends the mini experiment to all nine languages and will confirm or challenge the pattern across the full morphological spectrum.

Mini-scale data limits

At 2M parameters / 5M tokens the models are severely data-limited - Arabic bundle accuracy of 9.3% reflects data starvation more than engine quality. Mini results are lower bounds; small and medium scales are the next steps where mini signal justifies the compute.

Arabic engine nominal gap

Misfires on some nominals and adjectives - Form II masdars and nisba forms occasionally misclassified. Verbal forms are correct. The 13.9% improvement holds despite the errors; Arabic numbers are a lower bound.

Vocabulary sizing is a design parameter

Each morph vocabulary is designed with a hard size limit from the start - avoiding the embedding-table explosion seen when enumerating all root-POS combinations without constraint. Bundle-level clustering keeps the feature space bounded.

6. Conclusion

Language structure can function as an efficiency variable in language models. That is the claim this project started with, and the Phase 1 pilot supports it directionally: morphology-aware preprocessing reduces the computational cost of training in proportion to the morphological complexity of the language. The more grammar a language packs into word form, the more the model benefits from being told about it upfront.

The pattern in Phase 1

Turkish gains 56.9%, Arabic gains 13.9%, English gains ~1% - a monotonic gradient matching the predicted ordering of morphological complexity. Phase 3 extends the mini experiment to nine languages, adding Mandarin as a near-zero control, German and Spanish as fusional midpoints, Hungarian as an agglutinative-fusional hybrid, and Swahili and Basque as structural outliers alongside Arabic.

With all nine engines built and tested, the pipeline is ready to extend the pattern across the full morphological spectrum. The ultimate goal is to derive a quantitative relation between a language's grammatical shape and the compute required to train a capable model in it - a result that would have implications for accessibility, linguistic equity, and the sustainability of AI systems.
